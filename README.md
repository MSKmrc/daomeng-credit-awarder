# 到梦空间学分助手

用电脑控制安卓手机上的「到梦空间」APP，按 Excel 名单批量颁发活动学分。
读名单 → 校验学号姓名 → 逐个搜索颁发 → 结果写回 SQLite 并导出 Excel，中断后可断点续跑。

## 双版本说明

本仓库提供三个构建目标：

| 构建目标 | 入口 | 用途 |
| --- | --- | --- |
| `general` | `DM.py` | 通用单人搜索发分 |
| `surname` | `DM_surname.py` | 按姓氏搜索，逐个勾选后批量颁发 |
| `surname-one-point` | `DM_surname.py` | 强制分值 1.0 的姓氏批量版 |

姓氏批量构建产物名称包含“按姓氏”时，会自动进入批量模式；源码运行时使用：

```bat
python DM_surname.py --surname-batch
```

当前搜索统一使用手机系统输入法：文字通过 Android 无障碍接口写入，再点击键盘右下角的“搜索”键，不安装或依赖 AdbKeyboard。

## 一、准备手机

1. 安卓手机打开 **开发者选项**（设置 → 关于手机 → 连点版本号）
2. 开启 **USB 调试**；用无线调试的话再开启 **无线调试**
3. 手机上安装并登录「到梦空间」APP（需具备该活动的**学分管理**权限）

- 有线：数据线连电脑，手机上确认「允许 USB 调试」
- 无线：手机无线调试页查看 IP:端口 与配对码，用 `-p` 配对、`-d` 连接

第一次在一台手机上使用时加 `-i` 参数，脚本会自动把自动化依赖装到手机上。

## 二、两种运行方式

### 方式 A：直接用 exe（推荐）

**直接双击 `到梦空间学分助手.exe`**，会进入一步步问答的向导：
它会先列出当前目录和桌面上的表格让你选编号，也可以把表格直接拖进窗口。
**向导的顺序固定为三步走**（文件名不会被解析，分数全看你现场填的数字）：

1. **录取名单** —— 系统自动按 0 分处理，它只做姓名核对基准，本身不发分
2. **1 分名单** —— 选好文件后输入 `1.0`
3. **2 分名单** —— 选好文件后输入 `2.0`（没有就直接回车结束添加）

接着是可选的补充名单 / 账号表 / 易班名单（都可直接回车跳过），然后是连接方式：

- 数据线：直接回车
- 无线调试：填手机的 `IP:端口`，例如 `192.168.1.100:5555`

最后填完开关项、确认汇总信息 → **就开始自动发放**了。发放过程不需要人管，每发完一个人更新一次 SQLite 进度，中途断了可用 `-r` 续跑。

> - 找不到文件时把表格**拖进窗口**再回车最快
> - 出错时窗口会停住让你看完提示，不会一闪而过（批处理里加 `--no-pause` 可关闭暂停）
> - exe 已自带 adb（platform-tools），不需要安装 Android SDK

想跳过向导、一步到位，就在 exe 所在目录打开命令行（`Shift + 右键` → 在此处打开 PowerShell）：

```bat
到梦空间学分助手.exe -f "D:\名单\录取名单.xlsx" 0 -f "D:\名单\一等奖.xlsx" 1.0 -d 192.168.1.100:5555
```

### 方式 B：源码运行

```bat
pip install -r requirements.txt
:: 把 Android SDK 的 platform-tools 文件夹放到 daomeng\platform-tools\ 下
python DM.py -f "D:\名单\录取名单.xlsx" 0 -f "D:\名单\一等奖.xlsx" 1.0
```

按姓氏批量版：

```bat
python DM_surname.py --surname-batch
```

构建三个版本：

```bat
python build_exe.py --variant general
python build_exe.py --variant surname
python build_exe.py --variant surname-one-point
:: 或一次构建全部
python build_exe.py --variant all
```

姓氏批量版会：

- 预检录取名单和发分名单。
- 同一学号、同一姓名的完全重复行只保留一行。
- 只有两分名单去重后仍出现同名不同学号时才归入歧义重名。
- 按姓氏搜索，逐人点击右侧小勾选框。
- 当前组有缺失时滚回顶部二次查找一次。
- “请求数据失败”等待 20 秒后最多自动重试 3 次。
- 连续失败 3 次后等待 30 秒再关闭和锁屏。
- 结果写入桌面 `到梦空间发分结果\按姓氏批次-时间`。
- 正常结束时显示“鸣谢usc易班工作站技术部and行政部”。

adb 的查找顺序：`ADBUTILS_ADB_PATH` 环境变量 → 随包携带的 platform-tools → 程序目录 → `ANDROID_HOME` → 系统 `PATH`。

## 三、Excel 名单格式

所有名单文件的**第一行必须是表头**。只有**录取名单**（分值为 0 那份）额外需要一个 `活动名称` 列，列里任意一行填上活动名即可（脚本取第一个非空值）；发分名单不需要这一列。

| 名单类型 | 必需列 | 说明 |
| --- | --- | --- |
| 录取名单（分值固定写 `0`） | `学号`、`姓名`、`活动名称` | 作为核对基准，本身不发分；**发分名单里的人必须都在其中**，否则会被判为「未报名」跳过 |
| 发分名单（分值 > 0） | `学号`、`姓名` | 学号支持从任意文本中提取 11 位数字（` 前缀、前后空格都不影响） |
| 补充名单（`-a`，可选） | `学号`、`姓名`、`分值` | 额外追加/覆盖的人员 |
| 易班映射 CSV（`-yb`，可选） | `姓名`、`学号`、`易班ID` | 名单没有学号列时用它补全 |
| 账号表（`-u`，可选） | `账号`、`密码` | 掉登录时自动重登 |

学号规则默认是 **11 位连续数字**（见 `daomeng/file_manager.py::_extract_student_id`），位数不同的学校改这里即可。

## 四、常用参数

| 参数 | 说明 |
| --- | --- |
| `-f 文件路径 分值` | 必填，可重复；录取名单分值必须为 `0` |
| `-d IP:PORT` | 无线调试连接地址，不填则尝试有线 |
| `-p IP:PORT 配对码` | 无线调试配对 |
| `-i` | 初始化设备（第一次连接或连接异常时用） |
| `-a 补充名单.xlsx` | 额外添加名单 |
| `-u 账号表.xlsx` | 掉登录时自动重登 |
| `-yb 易班名单.csv` | 易班 ID → 学号映射 |
| `-r 上次任务目录` | 断点恢复，**不能再改** `-f`/`-a`/`-yb` |
| `--click-other-tab` | 搜索前先点「已获得其他学分」页签 |
| `-cl / -fl` | 控制台 / 文件日志级别 |

## 五、运行流程与结果

1. 每次运行会在**程序所在目录**生成 `<活动名>-<时间戳>\` 文件夹
2. 里面包含 `automation.log`（排错用）和 `students.db`（进度）
3. 正常结束后导出 `<活动名>.xlsx`，并清理掉 db 等中间文件，**只留 Excel**
4. 中途断了用 `-r "那个文件夹"` 继续，未完成的人会自动跳过已处理的

任务可能用到的状态：

| 状态 | 含义 | 要不要管 |
| --- | --- | --- |
| 成功颁发 N 分 | 已发出 | 不用管 |
| 未知(提示:…) | 点完确定但没读到成功提示 | **要核对**，可能是重复颁发 |
| 待核查（学号搜索无结果，已跳过） | 按学号没有搜到结果 | **要核对**，程序直接跳过下一位 |
| 待核查（搜索到结果但姓名不符，已跳过） | 搜到结果但姓名不一致 | **要核对**，程序直接跳过下一位 |
| 待核对（姓名不符） | 学号查到的人名对不上 | **要核对** |
| 学号错误 / 颁发失败 | 数据或设备问题 | **要核对** |

> 「待核对」的不会被自动重发（恢复任务只重跑「未处理」的人），也不会点颁发，**重复发分风险比旧版低很多**。
> 但「点确定之后」的异常重试仍存在理论上的重复颁发风险，遇到「未知」状态请先在 APP 里核对再决定。

> 安全说明：`config.json` **不会保存密码**。恢复任务时如果没有重新传 `-u`，会提示输入密码（直接回车则改为手动登录）。

## 六、速度参考

单人流程固定要为：输入学号 → 搜索 → 点人 → 点颁发 → 点确定 → 等服务端返回 → 读结果提示。
实测节奏大概 **3～5 秒/人**（手机性能好 + 数据线能到 3 秒内，无线调试或 APP 卡顿会到 6～8 秒）。

| 规模 | 预计耗时 |
| --- | --- |
| 100 人 | 5～8 分钟 |
| 500 人 | 25～40 分钟 |
| 1400 人 | 1.5～2.5 小时 |

进度条下方会实时显示「平均 N 秒/人｜剩余 X 人，预计还需 …」，每人的耗时也会记在日志里（`-cl DEBUG`）。
对比人工点一个人约 15～30 秒，1400 人的人工量在 6～12 小时。

想跑快一点：**用数据线别用无线**（每次界面 dump 快 2～3 倍）、手机保持常亮并关掉省电、
跑的时候别在手机上干别的事。大批量的话建议分批（比如每批 300 人），中途有事也方便停。

### 想再快一个量级？先探测 APP 是否支持批量

APP 底部那个按钮的文字是「**颁发1人**」（resourceId `tv_step`）——文字里的数字往往跟着勾选人数变。
若那边支持「勾选多人 → 一次颁发」，速度会是现在的 **10 倍以上**。跑一下探测模式确认：

```bat
:: 自动导航到发分页后导出控件树
到梦空间学分助手.exe --probe -f "D:\名单\录取名单.xlsx" 0 -f "D:\名单\1分.xlsx" 1.0 -i

:: 或者你自己把手机停在某页，直接导出当前屏幕
到梦空间学分助手.exe --probe
```

会在 exe 同目录生成 `probe-<时间戳>\probe.txt`（重点控件清单 + `hierarchy.xml` 原始树）。
看清单里有没有 **checkable=true 的复选框**，有的话就能改造成批量模式。

另外两条官方路径，能用就别用自动化：

- **网页管理后台 <http://www.5idream.net/>**（校/院管理员账号）：支持 Excel 模板批量导入，
  1400 人几分钟搞定。学校通常叫「第二课堂成绩单网络管理系统」。
- **成长记录批量补录**：走院里二课工作部提交批量模板（一般叫《成长记录批量导入模板》），同样秒级。

## 七、常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 adb（platform-tools） | 用自带 adb 的完整版程序；或把 platform-tools 放到程序目录；或设置 `ANDROID_HOME` |
| `切换 AdbIME 失败` | 手机不允许安装/启用输入法，手动安装后在手机输入法设置里允许「ADB Keyboard」 |
| 一直卡在某个界面 | 用 `-cl DEBUG` 看日志确认卡在哪一步；大概率是 APP 改版，需要更新 `daomeng/selectors.py` 里的选择器 |
| 搜索不到活动 | 确认活动在「我的活动 → 管理」中，且活动名与 Excel 里完全一致 |
| 设备掉线 | 自动重连一次；失败会提示输入新的 IP:端口，或留空改用有线 |
| 学生提示「未找到」 | 该生不在录取名单或已发过分，检查活动签到情况 |

## 八、打包成 exe

```bat
pip install -r requirements.txt
python build_exe.py            :: 单文件版，产物 dist\到梦空间学分助手.exe
python build_exe.py --onedir   :: 目录版，启动更快
```

## 九、注意

- 同一时间只支持**一台设备**（脚本用单个 `self.score` 记录当前分值）
- APP 改版后要先更新 `daomeng/selectors.py`，改完建议先跑单个学生验证
- 学分发放属于不可逆操作，正式批量前建议先用小名单试跑
